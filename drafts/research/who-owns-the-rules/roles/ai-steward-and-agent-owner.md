# AI steward and agent owner

People who admit, register, permission and retire agents, or sponsor them. Titles seen: AI Steward, AI Steward - Governance, AI Agent Governance Specialist, Agent Management Analyst, Copilot / Copilot Studio Governance Engineer, Copilot Platform Administrator. Platform roles (assigned to people inside a product rather than hired as titles): agent sponsor, agent owner, agent manager, Agent ID Administrator, Agent Registry Administrator (Microsoft Entra); AI steward, AI asset owner (ServiceNow); agent owner (SailPoint, Okta).

Collected 10 October 2026 from web search result summaries only (no page was opened). Every item is graded **S** (search summary only). Quotation marks mark wording that appeared in a search result; the search tool summarises pages, so quoted words may be the summariser's and should be checked against the source.

## Status

Two layers show up. As a job title, "AI Steward" predates the agent wave in the evidence: ServiceNow's "AI Steward - Governance" (Santa Clara) and an "AI steward govenance" listing under Element AI on the DCVC job board are about data and model governance, undated in the results. Thomson Reuters' current "AI Steward" (about September 2026) adds "large language models and AI agents" to a model-governance remit. Agent-specific titles appear only in 2026-era evidence and are rare: Jungheinrich's "AI Agent Governance Specialist", Dun & Bradstreet's "Agent Management Analyst" and Microsoft-tenant governance roles (Milbank, GHD, Merative). As a platform role, sponsor/owner/manager for agents is defined by Microsoft Entra Agent ID (documentation changes logged 19 November 2025; Zero Trust workshop guidance) and AI steward/AI asset owner by ServiceNow AI Control Tower (Zurich and Australia release docs, updated 12 March 2026); SailPoint and Okta assign a named human owner per agent. Scale signal: a SANS 2026 non-human-identity survey summary reports that 74% of organisations deploy AI agents or automations that need credentials or access permissions (secondary, via vendor blog). Commonness: as a hired title, uncommon (single postings per title); as an assigned responsibility, built into the major identity and ITSM platforms, so likely far more widespread than titles suggest. A SailPoint research post calls agent access review not as established as human review (paraphrase).

## Capability models

### A. Microsoft Entra Agent ID — agent owners, sponsors and managers
- Owner: Microsoft. Year: 2025–2026. URLs: mirror of the Learn page https://dotnet.territoriali.olinfo.it/en-us/entra/agent-id/agent-owners-sponsors-managers (the official Learn URL did not surface); Zero Trust workshop guidance https://microsoft.github.io/zerotrustassessment/ja/docs/workshop-guidance/AI/AI_012 . Grade S.
- Roles as defined:
  - Sponsor: business accountability; decides whether an agent should continue; requests access packages with business justification; required at agent identity creation; needs a succession plan; decides renewal, extension or removal; during incidents judges whether behaviour is expected and authorises responses such as suspension. Groups can be sponsors.
  - Owner: "technical administrators who manage credentials, configuration, and authentication properties"; can add or update other owners and sponsors.
  - Manager (one source only): user responsible for the agent in the organisation's hierarchy; can request access packages for reporting agents.
  - Separation of duties: these relationships are separate from RBAC admin roles such as Agent ID Administrator.

### B. Microsoft Entra built-in roles for agents
- Owner: Microsoft. Year: 2025 (change log 19 November 2025). URLs: https://learn.microsoft.com/en-us/entra/agent-id/authorization-agent-id ; https://docs.azure.cn/en-us/entra/identity/role-based-access-control/permissions-reference ; https://entradiff.merill.net/2025-11-19.html . Grade S.
- Agent ID Administrator (privileged): manage all aspects of agents in a tenant, including identity lifecycle for agent blueprints, blueprint principals, agent identities and agentic users.
- Agent ID Developer: create agents.
- Agent Registry Administrator: manage all aspects of the Agent Registry; organise agents into collections, control registry access, assign registry roles (last two per a secondary Topedia summary).

### C. ServiceNow AI Control Tower roles
- Owner: ServiceNow. Year: 2026 (Zurich/Australia docs updated 12 March 2026). URL: https://www.servicenow.com/docs/r/_yCRwrQYX6H0b46tCsDNZA/TSKwR8PkgQG9yG2O9fuJEw . Grade S.
- AI steward (assigned by the organisation): configure AI Control Tower; promote AI governance practices; link the AI asset inventory to the tool; run its initiatives; understand AI assets and platform policies; create AI assets and handle their full lifecycle; manage asset lifecycle, policy adherence, playbooks, third-party model configuration and approval workflows; turn on hyperscaler connections for AI discovery; manage AI Gateway MCP server settings.
- AI asset owner: keep AI assets accurately recorded and maintained; update deployment phases.
- Workspace user: owns and manages AI assets.

### D. ServiceNow AI Governance (store app) — AI Steward role
- Owner: ServiceNow. Year unknown. URL: https://apprepo.service-now.com/store/app/e749ebae1be06a50a85b16db234bcb6f . Grade S.
- AI Steward: facilitate and coordinate governance activities between Innovation, Legal, Security, Risk and Compliance teams; alongside an AI asset inventory of models, datasets and prompts.

### E. Microsoft Cloud Adoption Framework — governance and security for AI agents across the organisation
- Owner: Microsoft. Year: 2025–2026. URL: https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ai-agents/governance-security-across-organization . Grade S.
- Points listed: give agent governance to the leaders who own cloud governance, security and compliance (no parallel model); formalise agent accountability with defined authority and decision rights; discover and classify all agents into a complete inventory; treat shadow deployments as security and cost risks. No standard owner-role set defined.

### F. IAPP AI Governance Professional (AIGP) Body of Knowledge v2.1
- Owner: IAPP. Year: effective 2 February 2026 (official page in results still showed v2.0.1). URL: https://iapp.org/certify/body-of-knowledge-aigp ; secondary https://trainingcamp.com/articles/how-to-study-for-the-aigp-a-learning-path-built-around-the-bok-v2-1-blueprint/ . Grade S.
- Domains: I Foundations; II Laws, Standards and Frameworks (II.C beyond EU AI Act; II.D references ISO 42005); III Governing AI Development; IV Governing AI Deployment and Use (IV.A adds Agentic Architectures).

### G. Cloud Security Alliance — Agentic Identity Governance Framework v1 (draft)
- Owner: Cloud Security Alliance Labs. Year: 27 March 2026 (draft). URL: https://labs.cloudsecurityalliance.org/research/agentic-identity-governance-framework-v1/ . Grade S.
- Content listed: replace standing agent privileges with intent-declared, time-bound, scope-limited grants; decommissioning and monitoring; evaluates OAuth 2.0/OpenID Connect, SPIFFE/SPIRE and SCIM.

### H. SailPoint Agent Identity Security and Okta Resource Access Certifications for AI Agents
- Owners: SailPoint; Okta. Year: 2025–2026. URLs: https://documentation.sailpoint.com/saas/help/agent/index.html ; https://www.sailpoint.com/lp/products/agent-identity-security ; https://www.okta.com/blog/product-innovation/resource-access-certifications-for-ai-agents/ ; https://learning.okta.com/transition-to-managed-identities . Grade S.
- Roles/tasks: assign one or more human owners to every agent, with succession when roles change (SailPoint); certification campaigns in which owners review agent access (both); register agents as managed identities with named owners accountable for access requests and certification reviews (Okta course).
