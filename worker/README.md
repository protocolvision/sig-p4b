# Sign-up Worker

A small Cloudflare Worker that stores session sign-ups for the SIG and exports them for emailing.
It is self-contained: this folder plus `../config.json` is everything needed to run it on any
Cloudflare account.

## What it does

| Route | Purpose |
|---|---|
| `POST /signup` | Register or update a member (JSON from the site's dialog, or a plain form post). Email is required; name, website, GitHub, Discord, and affiliation are optional. Registering again merges: new non-empty fields update the record, empty ones keep what's there, and the original signup date, source, and role are kept. |
| `GET /export.csv` | The full list as CSV, with a signed unsubscribe link per person. Requires the `X-Export-Secret` header. |
| `GET /unsubscribe?email=…&t=…` | One-click unsubscribe (the link from the export). |

Storage is one KV namespace (`SIGNUPS`): `sub:<email>` holds a member, `rl:<ip>:<hour>` holds rate-limit
counters (10 requests per hour per IP). Roles are `member` or `pi-core`.

## Everyday use

    ./export.sh                    # writes signups-YYYY-MM-DD.csv (gitignored)
    npx wrangler deploy            # after changing src/index.ts

`export.sh` reads the Worker's address from `../config.json` and the secret from
`~/.config/sig-p4b/export_secret`.

## Running it yourself (new maintainer, new account)

If the current maintainer leaves, anyone can stand this up on their own Cloudflare account:

1. **Deploy.** From this folder: `./setup.sh`. It logs you in, creates the KV namespace, generates
   and uploads an export secret, deploys, and writes the new Worker URL into `../config.json`.
2. **Point the site at it.** From the repo root: `./deploy.sh` (or push to `main` if CI publishing is
   set up). The site's Register dialog, `llms.txt`, and `export.sh` all read the URL from `config.json`.
3. **If the site moved too,** set `SITE` and `ALLOWED_ORIGINS` in `wrangler.jsonc` (`vars`) and run
   `npx wrangler deploy` again. Browsers can only call `/signup` from the origins listed there.
4. **Bring the member list over.** Ask the previous maintainer for an export (or run `export.sh`
   against the old Worker), then `python3 import.py old.csv --dry-run` and `python3 import.py old.csv`.
   Roles and original signup dates are kept; unsubscribe links are regenerated by the new Worker.
5. **Commit** `wrangler.jsonc` and `config.json`. They contain no secrets: the namespace id is not a
   credential, and the export secret stays in `~/.config/sig-p4b/`.

The member list is personal data. Keep exports out of the repo, share them only with the next
maintainer, and delete the old Worker and namespace once the move is confirmed.
